# TypeScript 에러 처리와 타입 가드

## 1. `catch (error)`의 `error`는 왜 `unknown`일까?

`try...catch` 문에서 발생하는 에러는 어떤 타입이든 될 수 있다. `Error` 객체일 수도, 단순 문자열일 수도, 심지어 `null`일 수도 있다.

```tsx
typescript

 Show full code block
try {
// throw new Error("에러 객체!");// throw "문자열 에러!";// throw { message: "객체 에러!" };
} catch (error) {
// 여기서 error의 타입은? -> unknown
}

```

타입스크립트는 이런 불확실성으로부터 코드를 보호하기 위해 `catch` 블록의 `error` 변수 타입을 기본적으로 `unknown`으로 추론한다.

- **`any` vs `unknown`**:
    - `any`: "타입 검사를 포기할게. 뭐든지 할 수 있어." (위험)
    - `unknown`: "무슨 타입인지 모르겠어. 사용하려면 네가 타입을 증명해야 해." (안전)

`unknown`은 **타입이 무엇인지 확실히 알기 전까지는 아무것도 할 수 없도록 강제**하여 코드의 안정성을 높인다.

## 2. `Type 'unknown' is not assignable to type '{...}'` 에러

이 에러는 `unknown` 타입을 더 구체적인 타입에 직접 할당하려고 할 때 발생한다.

```tsx
typescript

 Show full code block
// ❌ 에러 발생try {
// ...
} catch (error) {
// 'error'는 unknown인데, 특정 객체 타입 'e'에 할당하려고 함const e: { message?: string } = error;
}

```

컴파일러는 `error`가 `{ message: string }` 구조를 가졌다고 보장할 수 없기 때문에 이 할당을 막는다. 이것이 타입스크립트가 의도한 정상적인 동작이다.

## 3. 타입 가드(Type Guard)로 안전하게 타입 좁히기

`unknown` 타입을 안전하게 사용하려면 **타입 가드**를 통해 타입을 좁혀야(narrowing) 한다.

### 타입 가드의 핵심: `if` 블록과 `in` 연산자

`if` 문과 `in` 연산자를 사용하면 객체에 특정 속성이 있는지 런타임에 확인할 수 있다.

```tsx
typescript

 Show full code block
// ✅ 올바른 패턴try {
// ...
} catch (error: unknown) {
// 1. 'error'가 객체인지, 그리고 내부에 'error' 속성이 있는지 확인if (
    error &&
    typeof error === "object" &&
    "error" in error &&
    error.error &&
    typeof error.error === "object"
  ) {
// 2. 이 if 블록 안에서는 error.error가 객체임이 보장된다.// 이제 안전하게 속성에 접근할 수 있다.if ("email" in error.error && typeof error.error.email === "string") {
      console.log(error.error.email);
    }
  }
}

```

- **`"속성이름" in 객체`**: `in` 연산자는 객체(및 프로토타입 체인)에 해당 속성이 존재하는지 확인하는 자바스크립트 문법이다. 타입스크립트는 이 결과를 보고 타입을 추론한다.
- **스코프 주의**: 타입 가드의 효력은 **오직 해당 `if` 블록 내부에서만 유효**하다. 블록을 벗어나면 변수는 다시 원래의 `unknown` 타입으로 돌아간다.

## 4. 데이터 흐름과 타입 변환의 올바른 위치

> 시나리오: 폼 입력값(string)을 API로 전송할 때는 number로 보내야 한다.
> 

이런 경우, 타입 변환은 어디서 해야 할까? **데이터의 역할이 바뀌는 경계**에서 하는 것이 가장 좋다.

1. **폼 계층 (`SignupForm.tsx`)**:
    - `useForm`의 `defaultValues`와 `zod` 스키마는 `phoneNum`을 `string`으로 관리한다. (HTML `<input>`의 값은 항상 `string`이므로 자연스럽다.)
2. **제출 계층 (`onSubmit` 함수)**:
    - 폼에서 유효성 검사를 통과한 `string` 타입의 `values.phoneNum`을 받는다.
    - API 호출 직전, `mutateAsync`에 전달하는 객체 안에서 `Number(values.phoneNum)`를 통해 `number` 타입으로 변환한다. **바로 여기가 최적의 변환 시점이다.**
    
    ```tsx
    typescript
    
     Show full code block
    // SignupForm.tsxconst onSubmit = async (values: SignupFormValues) => {
      await signupMutation.mutateAsync({
    // ...phoneNum: Number(values.phoneNum),// ✨ UI(string) -> API(number) 변환 지점
      });
    };
    
    ```
    
3. **API 통신 계층 (`userService.ts`)**:
    - `signup` 함수는 API 명세에 따라 `phoneNum`을 `number` 타입으로 받도록 정의한다.

이렇게 계층별로 역할을 명확히 분리하면 코드가 훨씬 깔끔해지고 예측 가능해진다.
