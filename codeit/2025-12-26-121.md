# Next.js Hydration 오류 및 useEffect setState 경고 해결 과정

## 문제 상황

### 에러 1: useEffect 내 setState 동기 호출 경고
```
Error: Calling setState synchronously within an effect can trigger cascading renders
```

### 에러 2: Hydration 오류
```
Hydration failed because the server rendered HTML didn't match the client.
```

---

## 원인 분석

### 1. useEffect 내 setState 문제
- **원인**: `useEffect` 내에서 `setState`를 동기적으로 호출
- **문제 코드**:
  ```typescript
  useEffect(() => {
    setIsMounted(true);
    setHasAccessToken(!!localStorage.getItem("accessToken"));
  }, []);
  ```
- **이유**: React는 effect 내부의 동기적 setState를 권장하지 않음 (성능 문제)

### 2. Hydration 오류 문제
- **원인**: 서버와 클라이언트의 초기 렌더링 결과가 다름
- **서버**: `localStorage` 접근 불가 → 항상 `false` 반환
- **클라이언트**: `localStorage` 접근 가능 → 실제 값 사용
- **결과**: 서버 HTML과 클라이언트 첫 렌더링 결과 불일치

---

## 해결 과정

### 시도 1: eslint-disable 주석 (임시 해결)
```typescript
useEffect(() => {
  // eslint-disable-next-line
  setIsMounted(true);
  setHasAccessToken(!!localStorage.getItem("accessToken"));
}, []);
```
- **문제**: 근본적인 해결이 아님, 단순히 경고 무시

### 시도 2: 커스텀 훅 분리
- **문제**: 과도한 해결책, 새 파일 생성 필요

### 최종 해결: useState Lazy Initialization
```typescript
const [hasAccessToken] = useState<boolean>(() => {
  if (typeof window === "undefined") return false;  // 서버
  return !!localStorage.getItem("accessToken");     // 클라이언트
});

const [isMounted] = useState<boolean>(() => {
  return typeof window !== "undefined";
});
```

---

## 해결 원리

### Lazy Initialization이란?
- `useState`에 함수를 전달하면 **첫 렌더링에 한 번만 실행**됨
- 이후 리렌더링에서는 실행되지 않음

### 왜 해결되는가?

#### 서버 렌더링
```typescript
typeof window === "undefined"  // true
→ hasAccessToken = false, isMounted = false
→ useAuth(false) → enabled = false → 쿼리 실행 안됨
→ isLoading = false
→ if (!isMounted || isLoading) = if (true || false) = true
→ "로딩중..." 렌더링 ✅
```

#### 클라이언트 첫 렌더링 (Hydration 시점)
```typescript
typeof window !== "undefined"  // true
→ hasAccessToken = true, isMounted = true
→ useAuth(true) → enabled = true → 쿼리 시작
→ isLoading = true (쿼리 진행 중)
→ if (!isMounted || isLoading) = if (false || true) = true
→ "로딩중..." 렌더링 ✅
```

**핵심**: 서버와 클라이언트 모두 첫 렌더링에서 "로딩중..."을 보여줌 → Hydration 성공!

## 최종 코드

```typescript
"use client";

import { useAuth } from "@/hooks/useAuth";
import Button from "../common/button";
import { useRouter } from "next/navigation";
import { useState } from "react";

export default function Header() {
  const router = useRouter();
  
  // Hydration 오류 방지: 서버와 클라이언트 초기 렌더링을 일치시키기 위해
  // lazy initialization 사용 (첫 렌더링에 한 번만 실행)
  const [hasAccessToken] = useState<boolean>(() => {
    // 서버에서는 window 객체 없으므로 항상 false 반환
    if (typeof window === "undefined") return false;
    // 클라이언트에서는 window 객체 있으므로 localStorage에 accessToken이 있는지 확인
    return !!localStorage.getItem("accessToken");
  });

  const [isMounted] = useState<boolean>(() => {
    // 서버에서는 window 객체 없으므로 항상 false 반환
    // 클라이언트에서는 window 객체 있으므로 항상 true 반환
    return typeof window !== "undefined";
  });

  // 마운트 여부와 accessToken 여부를 조합하여 useAuth 훅 호출
  const { me, isGuest, isLoading } = useAuth(isMounted && hasAccessToken);

  // 서버와 클라이언트 초기 렌더링 일치를 위해 마운트 전에는 로딩 상태 표시
  if (!isMounted || isLoading) {
    return (
      <header>
        <span>로딩중...</span>
      </header>
    );
  }

  return (
    <header>
      {isGuest ? (
        <Button
          text="로그인"
          onClick={() => router.push("/login")}
          variant="outline"
          width="100px"
        />
      ) : (
        <>
          <span>{me?.name}</span>
        </>
      )}
    </header>
  );
}
```

---

## 핵심 포인트

1. **useEffect 제거**: 외부 시스템(localStorage) 접근은 `useState` lazy initialization으로 처리
2. **서버/클라이언트 일치**: 초기 렌더링에서 항상 같은 결과 보여주기
3. **isLoading 활용**: 클라이언트 첫 렌더링에서 쿼리가 시작되면 `isLoading = true`가 되어 서버와 동일한 "로딩중..." 상태 유지
4. **Hydration 성공**: 서버 HTML과 클라이언트 첫 렌더링 결과 일치 → 오류 없음

- localStorage 같은 브라우저 API는 항상 `typeof window` 체크 필요
