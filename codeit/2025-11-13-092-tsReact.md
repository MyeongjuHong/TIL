# React TypeScript

## Type vs Interface

- 확장 가능, but 문법 차이 O

```ts
// type 확장
type EmployeeType = UserType & { department: string };

// interface 확장
interface EmployeeInterface extends UserInterface {
  department: string;
}
```

- type은 선언 병합 불가 (동일 이름으로 재선언 시 에러)

```ts
interface MergedInterface {
  a: number;
}

interface MergedInterface {
  b: string;
}

const merged: MergedInterface = { a: 1, b: "hello" }; // interface는 가능
```

- interface는 복잡한 타입 정의 불가

```ts
// type만 가능
type ID = string | number;
type Pair = [number, number];
```

### Interface

- 객체 구조만 정의 가능
- props 구조 정의에 주로 사용
- 라이브러리/프레임워크 api 정의 추천

### Type

- 유니온 타입, 튜플, 교차 타입 정의 가능

#### 유니온 타입

- 여러 타입 중 하나만 허용하는 타입

```ts
type ID = string | number; // 문자열 또는 숫자만 가능

const id1: ID = 123; // ✅ 가능
const id2: ID = "MJ"; // ✅ 가능
// const id3: ID = true;   // ❌ 에러, boolean 불가
```

#### 튜플

- 길이와 타입 고정된 배열

```ts
type Pair = [number, string]; // 0번째는 number, 1번째는 string

const p1: Pair = [1, "one"]; // ✅ 가능
// const p2: Pair = ["one", 1]; // ❌ 에러, 순서와 타입이 맞아야 함
```

#### 교차 타입

- 두 타입을 합쳐 모든 조건을 만족

```ts
type A = { a: number };
type B = { b: string };

type C = A & B; // a:number, b:string 모두 만족

const c: C = { a: 1, b: "hello" }; // ✅ 가능
```

## 제네릭

- 타입 고정 not yet, 사용 시점에 결정
- `타입의 매개변수`
- 재사용성↑, 코드중복↓, TS 추론 가능

```ts
function identity<T>(arg: T): T {
  return arg; // T -> 제네릭
}

const str = identity<string>("hello"); // T = string
const num = identity<number>(123); // T = number
```

### 제네릭 + 유니온 타입

```ts
// 성공/실패 API 응답을 유니온 타입 + 제네릭으로 정의
type ApiResponse<T> =
  | { status: "success"; data: T }
  | { status: "error"; error: string };
// API 응답처럼 상태에 따라 객체 구조가 바뀔 때 타입을 구분하고 싶을 때 리터럴 타입(정확한 하나의 값) 사용

// 사용 예시
const res1: ApiResponse<string> = { status: "success", data: "OK" };
const res2: ApiResponse<number[]> = { status: "success", data: [1, 2, 3] };
const res3: ApiResponse<any> = { status: "error", error: "Fail" }; // 그 외 타입은 에러
```

### 제네릭 + 튜플 타입

```ts
// 길이 2짜리 튜플을 제네릭으로 정의
type Pair<T, U> = [T, U];

const pair1: Pair<number, string> = [1, "MJ"];
const pair2: Pair<boolean, number> = [true, 99];
```

### 제네릭 + 교차 타입

```ts
type User = { id: number; name: string };
type Admin = { role: string };

// 제네릭 + 교차 타입
type Entity<T> = T & { createdAt: Date };

const user: Entity<User> = { id: 1, name: "MJ", createdAt: new Date() };
const admin: Entity<Admin> = { role: "super", createdAt: new Date() };
```

### 왜 props 정의에 type < interface?

1. 선언 병합 가능

- 동일 이름으로 선언 나눠 합치기 가능 (type은 불가능)
- 라이브러리에서 props를 점진적으로 확장하거나, 다른 라이브러리와 조합할 때 유리

2. 직관적인 상속 문법

- type도 & 연산자 가능하지만, extends 가독성이 더 직관적 + 문서화 EZ + 에디터 자동완성 진화적

3. React 커뮤니티/라이브러리 관행
