# ✅ **1. 패키지 설치**

### ✔ 왜 필요한가?

Next.js 기반 앱에서 **인증/데이터 fetching/폼 처리**를 안정적으로 구현하려면 다음이 필수입니다.

* **React Query** → 서버 상태 관리, 캐싱, 무한 스크롤 등
* **React Query Devtools** → 캐시와 요청 상태를 눈으로 확인
* **React Hook Form** → 빠르고 성능 좋은 폼 관리
* **Zod** → 입력값 유효성 검증(타입 안전성)
* **Zod Resolver** → RHF + Zod 자동 연결

### ✔ 어떤 역할을 하는가?

> 앱이 큰 규모로 성장해도 **데이터 fetching**, **인증 상태 관리**, **폼 처리**가 안정적으로 유지되도록 기반 패키지를 설치하는 단계

---

# ✅ **2. React Query Provider 세팅**

### ✔ 왜 필요한가?

React Query는 리액트 전역에서 쓰이기 때문에,
루트에서 **QueryClientProvider**로 감싸야 모든 컴포넌트에서 `useQuery`, `useMutation`을 사용할 수 있습니다.

### ✔ 어떤 역할을 하는가?

* React Query 전역 상태 저장소 생성
* 캐싱/자동 refetch 구동
* Devtools 기능 활성화

즉, **React Query가 작동하기 위한 루트 환경 구축 단계**입니다.

---

# ✅ **3. apiClient (fetch wrapper) 생성**

### ✔ 왜 필요한가?

Next.js 클라이언트는 fetch를 직접 호출할 때마다 다음을 반복해야 합니다:

* baseURL 적기
* headers 세팅
* credentials 설정
* JSON 직렬화
* 에러 핸들링

이걸 매번 쓰면 **중복 지옥**이 됩니다.

그래서 **fetch를 한 번 래핑해두고 모든 API 요청을 이 함수로 호출**합니다.

### ✔ 어떤 역할을 하는가?

* fetch 공통 설정 통일
* 쿠키 포함 설정 자동화
* 에러 처리 통일
* JSON 파싱 자동화

즉, **API 요청의 단일 진입점**입니다.

---

# ✅ **4. userService (API endpoint layer) 생성**

### ✔ 왜 필요한가?

프론트가 Express 서버로 요청할 때,
API Path(`/auth/login`, `/auth/me` 등)를 컴포넌트에서 직접 호출하면 로직이 흩어져서 유지보수 불가능해짐.

그래서 **service 레이어**가 필요합니다.

### ✔ 어떤 역할을 하는가?

* 모든 API 엔드포인트를 모아두는 곳
* Express 서버와 통신하는 함수 모음
* “login”, “logout”, “getMe”처럼 **도메인별 기능화** 담당

즉, **API 경로를 한 곳에서 관리하는 계층**입니다.

---

# ✅ **5. useApiQuery / useApiMutation 공통 훅 세팅**

### ✔ 왜 필요한가?

React Query의 `useQuery`, `useMutation`을 매번 직접 쓰면:

* queryKey를 매번 수동 설정
* retry 옵션 매번 설정
* staleTime 등 옵션 반복
* 에러 처리도 매번 중복

→ 서비스가 커지면 “옵션 중복 + 에러 중복 + key 충돌”로 유지보수 지옥 발생.

그래서 **공통 레이어**가 필요합니다.

### ✔ 어떤 역할을 하는가?

* 모든 API 호출에서 React Query 옵션을 **통일**
* retry/staleTime 등 “기본값”을 제공
* queryKey 자동 생성을 통해 충돌 감소
* 에러 처리 패턴 일원화

즉, **React Query 커스텀 추상화 레이어**입니다.

---

# ✅ **6. useAuth (유저 전용 훅) layer**

### ✔ 왜 필요한가?

유저 관련 API는 다음과 같은 전용 로직을 가짐:

* 로그인 시 `me` 캐시 invalidate
* 로그아웃 시 `me` 캐시 초기화
* refresh 토큰 발급 시 `me` 다시 요청
* 인증 실패 처리
* 프로필 정보 상태 유지

이걸 컴포넌트마다 직접 구현하면 중복 수백 줄 발생합니다.

### ✔ 어떤 역할을 하는가?

* userService + useApiMutation/useApiQuery 결합
* 유저 인증/로그인/로그아웃/refresh를 전용 로직으로 캡슐화
* 컴포넌트에서는 단지 “useLogin()”만 호출하도록 간소화

즉,
**“유저 인증 관련 모든 로직을 모아둔 전용 Layer”**입니다.

---

# ✅ **7. react-hook-form + zod 폼 세팅**

### ✔ 왜 필요한가?

로그인, 회원가입, 비밀번호 변경, 프로필 업데이트 등
🟥 입력값 검증이 필수적인 기능이 대부분입니다.

* 단순 `useState`로 폼 관리하면 재렌더링 지옥 + 성능 저하
* 유효성 검증을 직접 구현하면 중복 100%
* 타입 검증 없으면 런타임 에러 발생

그래서 “RHF + Zod” 조합을 사용합니다.

### ✔ 어떤 역할을 하는가?

* 고성능 폼 관리 (리렌더 최소화)
* Zod 스키마 기반의 타입/유효성 검증
* 서버로 보내기 전 값 자동 정제
* UI에서 에러 메시지 자동 관리

즉, **폼과 데이터 검증을 안전하고 빠르게 구현하는 Layer**입니다.
